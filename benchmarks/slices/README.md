# xitdb Per-Benchmark Code Slices & Odin vs. Zig Architectural Guide

[← Back to Benchmark Suite (`benchmarks/README.md`)](../README.md) · [**📘 Idiomatic Zig Optimization Guide (`zig-guide/README.md`)**](../zig-guide/README.md)

Across the **63 shared 1v1 benchmarks**, Odin (`-o:speed -microarch:native`) is faster on **62 / 63** benchmarks and Zig (`0.17.0-dev -Doptimize=ReleaseFast -Dcpu=native`) is faster on **1 / 63** (`#43 Compaction Heterogeneous DAG + dedup`), with **0 byte-footprint mismatches** (100% identical v1 wire output).

Each per-benchmark page below links directly to the exact `#L<start>-L<end>` line ranges in [`bench_xitdb.odin`](../bench_xitdb.odin), [`bench_xitdb.zig`](../bench_xitdb.zig), [`xitdb/*.odin`](../../xitdb), and [`reference/xitdb-zig/src/lib.zig`](../../reference/xitdb-zig/src/lib.zig), plus a dedicated engineering guide in [`benchmarks/zig-guide/`](../zig-guide/README.md) with drop-in Zig `0.17` implementations (~140 net LOC across all 6 subsystems).

## Cross-Language Architectural Summary: Why Odin is Faster & How to Improve Zig

| Subsystem (Benchmarks) | Odin Speedup | Verified Root Cause (`xitdb/*.odin` vs. `reference/xitdb-zig/src/lib.zig`) | Idiomatic Zig Improvement & Dedicated Guide |
| :--- | :--- | :--- | :--- |
| **Count-Augmented B-Tree (`Linked_Array_List`, `#20–#27`)** | **4.6x – 44.9x** | `BTREE_SLOT_COUNT = 16` (`146B` leaf, `274B` branch): Zig's [`readBTreeNode`](../../reference/xitdb-zig/src/lib.zig#L1946-L1972) / [`writeBTreeNodeAt`](../../reference/xitdb-zig/src/lib.zig#L1977-L1991) execute **18–34 unbuffered `takeInt`/`writeInt` calls** per node (decoding all 16 slots even when `num == 2`), and [`readBTreeSlot`](../../reference/xitdb-zig/src/lib.zig#L2023-L2042) decodes all 16 leaf slots just to read 1 slot (`44.1x` on `#21`). Odin ([`xitdb/btree.odin#L8-L181`](../../xitdb/btree.odin#L8-L181)) reads the node in **1 `core_read_exact`**, decodes `0..<num`, and seeks straight to `node_ptr + 2 + rem * 9` on leaf `get`. | Batch-read/write nodes via a stack `[146]u8` / `[274]u8` buffer (`0..node.num`) and short-circuit `.leaf` in `readBTreeSlot` → [**Guide 02**](../zig-guide/02_btree_node_batch_io_and_leaf_seek.md) |
| **Counted B+Tree (`Sorted_Map` / `Sorted_Set`, `#28–#38`)** | **4.1x – 51.3x** | Zig's [`sortedGet`](../../reference/xitdb-zig/src/lib.zig#L2634-L2658), [`sortedRank`](../../reference/xitdb-zig/src/lib.zig#L2683-L2707), and [`sortedPut`](../../reference/xitdb-zig/src/lib.zig#L2736-L2875) use **$O(16)$ linear scans** (`for (0..node.num)`), [`compareKey`](../../reference/xitdb-zig/src/lib.zig#L2612) zero-fills `256B` via `@splat(0)`, [`readSortedNode`](../../reference/xitdb-zig/src/lib.zig#L2481-L2511) issues **18–50 `takeInt` calls** per node, and [`sortedGetByIndex`](../../reference/xitdb-zig/src/lib.zig#L2661-L2680) decodes the whole leaf (`51.3x` on `#34`). Odin ([`xitdb/btree.odin#L1028-L1439`](../../xitdb/btree.odin#L1028-L1439)) uses **$O(\log_2 16)$ binary search** ($\le 4$ comparisons) and 1-read node decoding. | Extract `sortedBranchSearch` & `sortedLeafSearch` binary search helpers, drop `@splat(0)`, batch-decode `SortedNode`, and seek directly in `sortedGetByIndex` → [**Guide 03**](../zig-guide/03_sorted_bptree_binary_search.md) |
| **16-Way HAMT (`Hash_Map` / `Counted_Hash_Map`, `#1–#13`, `#45–#46`)** | **2.4x – 13.4x** | Inserting key+value in Zig ([`lib.zig#L3894-L3912`](../../reference/xitdb-zig/src/lib.zig#L3894-L3912)) runs **two full root-to-leaf traversals** (`putKey` + `put`). [`removeMapSlot`](../../reference/xitdb-zig/src/lib.zig#L1736-L1774) (`#11`, **13.35x**) zero-fills and reads/validates all 16 slots (`144B`) at every level before recursing, and [`readMapSlot`](../../reference/xitdb-zig/src/lib.zig#L1705-L1720) (`#10`, **6.58x**) recurses one shared nibble at a time. Odin ([`xitdb/hamt.odin`](../../xitdb/hamt.odin)) uses single-pass `Write_KV_Data` and lazy 1-slot descent on `remove`. | Read only the single child slot before recursing in `removeMapSlot` (reading `144B` on unwind only when `key_offset > 0` and child collapsed), and add single-pass `putKeyValue` → [**Guide 04**](../zig-guide/04_hamt_single_pass_kv_and_lazy_remove.md) |
| **16-Way Radix Trie & `CoreMemory` (`Array_List`, `#14–#19`)** | **2.1x – 4.5x** | [`CoreMemory.reader()`](../../reference/xitdb-zig/src/lib.zig#L4993-L5003) sets `.buffer = &.{}`, causing every `takeInt` / `readSliceAll` to miss `std.Io.Reader`'s inline fast path and execute **2 vtable calls** (`readVec` → `stream` → `Writer.fixed.drain`). Odin ([`xitdb/core.odin#L326-L340`](../../xitdb/core.odin#L326-L340)) slices `Core_Memory.buf` directly. | Back `CoreMemory.Reader` with `std.Io.Reader.fixed(written)` (refreshed in `seekTo()`), removing `CoreMemory.Reader.stream` (`-12 LOC`) → [**Guide 01**](../zig-guide/01_core_memory_zero_vtable_io.md) |
| **Streams, Bytes & Nested Paths (`#47–#57`)** | **1.3x – 8.7x** | [`Cursor.readBytesObject`](../../reference/xitdb-zig/src/lib.zig#L3295-L3316) (`#50`, **6.33x**) issues 3 unbuffered reads with a redundant `seekTo` before `format_tag`; `Cursor.Reader` chains vtables; `#55–#56` (`6.7x–8.7x`) compound B-Tree + B+Tree node overhead across 4 nested levels. | Drop the redundant `seekTo` in `readBytesObject`, return `.fixed(slice)` in `Cursor.reader()` when `comptime db_kind == .memory`, and apply Guides 01–03 → [**Guide 05**](../zig-guide/05_cursor_bytes_streams_and_paths.md) |
| **`CoreBufferedFile` & Lifecycle (`#58–#63`)** | **1.1x – 4.5x** | Every commit calls [`CoreBufferedFile.flush()`](../../reference/xitdb-zig/src/lib.zig#L5226-L5231) (`#59`, **4.06x**), which calls `memory.buffer.clearRetainingCapacity()` and resets `file_len = null`—evicting the hot tail window so the next tx pays ~15–20 unbuffered `preadv` syscalls + `fstat`. `#63` (`4.45x`) validates the trailer CRC-64/XZ twice (`init` + `rootCursor`). | Track `flushed_len: usize` in `CoreBufferedFile` so `flush()` writes dirty bytes without evicting the read window, and reuse the validated root `Slot` on open → [**Guide 06**](../zig-guide/06_buffered_file_tail_cache_and_compaction.md) |
| **Compaction & Replication (`#39–#44`)** | **Odin 1.2x–10.0x** (`#39–#42,#44`) / **Zig 1.15x** (`#43`) | Odin copies replication slices directly (`#39` **10.04x**). On `#43 Compaction (Heterogeneous DAG + dedup)`, **Zig wins by 1.15x** (`110.1 ms` vs `126.6 ms`) thanks to `std.AutoHashMap(u64, u64)`'s SIMD SwissTable metadata probing in [`Compactor`](../../reference/xitdb-zig/src/lib.zig#L4508-L4913). | Keep `std.AutoHashMap` in `Compactor`, apply Guide 01 for replication streaming, and batch-write `0..header.num` slots in `Compactor` → [**Guide 06**](../zig-guide/06_buffered_file_tail_cache_and_compaction.md) |
